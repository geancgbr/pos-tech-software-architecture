# Mitos sobre Testes de Software

| # | Mito | Realidade, segundo a apostila |
|---|---|---|
| 1 | Testes são **caros** e consomem muito tempo | Testes adequados **economizam** tempo e dinheiro a longo prazo: corrigir defeitos cedo evita problemas maiores. A **automação** reduz o tempo e acelera o ciclo |
| 2 | Devs conseguem **testar o próprio software** com eficácia | Podem fazer testes iniciais, mas têm uma **visão enviesada**. Testadores independentes trazem perspectiva imparcial e cenários não considerados |
| 3 | Testes garantem software **100% livre de erros** | **Impossível**, mesmo com testes rigorosos. Eles mitigam riscos e dão alto grau de confiança, mas não garantem perfeição |
| 4 | Testes são só para **grandes empresas** ou projetos complexos | São igualmente importantes em **qualquer tamanho e complexidade**. Até um app pequeno pode ter bugs |
| 5 | Testes só podem ser feitos **no fim do ciclo** | Devem ser incorporados **desde o início**. Testar continuamente evita retrabalho |
